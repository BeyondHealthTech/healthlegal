## 1. 結論（先に）

- **普及率はまだ半分強。** 電子カルテを入れている一般診療所は55.0%、一般病院は65.6%です（令和5年 医療施設調査）。400床以上の病院はほぼ入っている一方、200床未満の病院と診療所に未導入が残っています。
- **国の目標は「2030年に約100%」で、法律に書かれています。** しかも、ただ入れればよいのではなく、**オンプレミス型からクラウドネイティブ型へ刷新する**ことが方針の中心です。
- **「クラウドネイティブ」の中身が要件として決まりました。** 医科診療所・中小病院向けの標準仕様は、パブリッククラウド上で動くSaaSであること、マルチテナントであること、医療機関ごとのカスタマイズに応じない仕様であることなどを求めています。厚生労働省が製品を審査・認証する制度も始まり、**申請受付は2026年11月1日から**です。
- **ただし、楽観はできません。** 紙カルテの診療所の54.2%が「導入不可能」と答えた日本医師会の調査があり、病院向けのクラウド製品は限られていると国自身が書いています。国の普及推計も「一定の粗い仮定」を置いたものです。

以下、国の方針（2章）、普及状況（3章）、標準仕様と認証制度の中身（4章）、事業者が押さえる論点（5章）の順に、一次資料で確認します。

## 2. 国の方針: 2030年に「約100%」、しかもクラウドネイティブで

### 2.1 目標は工程表から法律へ

| 時期 | 出来事 | 内容 |
|---|---|---|
| 2023年6月 | 医療DX推進本部「医療DXの推進に関する工程表」 | 「遅くとも2030年には概ねすべての医療機関において必要な患者の医療情報を共有するための電子カルテの導入を目指す」 |
| 2025年1月 | 第6回「医療DX令和ビジョン2030」厚生労働省推進チーム | 病院の情報システムについて、オンプレミス型を刷新し、電子カルテ・レセプトコンピュータ・部門システムを一体的に、モダン技術を活用したクラウド型システムに移行する方針。国が標準仕様を作る |
| 2025年7月 | 第7回 同推進チーム | オンプレ型でカスタマイズしている現行の電子カルテから、「いわゆるクラウドネイティブを基本とする廉価なもの」への移行を図る。診療所向けは、SaaS型・マルチテナント方式のクラウド型サービス、標準APIの搭載、データ引き継ぎの互換性などを要件とする方向 |
| 2026年3月31日 | 標準仕様書（基本要件）1.0版を公開 | 医科診療所向け・中小病院向けの2種類 |
| — | 地域医療介護総合確保法 第12条の3第4項（国会修正で追加） | 「政府は、**令和12年12月31日までに、電子カルテの普及率…が約100％となることを達成**するよう、クラウド・コンピューティング・サービス関連技術…その他の先端的な技術の活用を含め…情報の電子化を実現しなければならない」 |
| 2026年7月21日 | 日本成長戦略 | 「オンプレミス型の医療機関情報システムをクラウドネイティブ型に刷新」。2028年度までに200床以上の病院（療養病床等が中心の病院を除く）で普及率100%、2030年までに普及率約100%・地域の拠点病院のサイバーセキュリティ対策100%・大病院向けクラウドネイティブ型製品の提供 |
| 2026年9月9日 | 厚生労働省「電子カルテ普及計画」 | 副題は「クラウドネイティブ型電子カルテの普及／全国的な医療情報の連携／サイバーセキュリティ対策の強化」 |
| 2026年10月16日 | 認証制度要綱 第1.0版を公表 | 標準仕様への適合を厚生労働省が製品ごとに審査・認証。**申請期間は2026年11月1日〜2027年10月31日** |

（出所: 電子カルテ普及計画 4〜5ページ、「電子カルテの普及について」5〜6ページ、標準仕様ページの「背景・目的」と「認証制度」の章）

ここで押さえておきたいのは、**目標が「電子化」から「クラウドネイティブ型への刷新」に変わってきた**ことです。普及計画は、クラウドネイティブ型への刷新によって、サイバーセキュリティ対策の強化と全国的なデータ連携基盤の構築を図ると書いています。

### 2.2 医療機関の種類ごとに、別の道を用意している

普及計画は、医療機関の状況に応じて支援策を分けています（普及計画 33ページ）。

| 医療機関の状況 | 国が想定する製品 |
|---|---|
| 電子カルテ未導入の診療所で、紙カルテを続けたいが国の医療DXサービスは使いたい | 「標準型電子カルテ・導入版」（クラウドネイティブ型、紙カルテ併用。医科無床診療所向け） |
| 電子カルテ未導入の診療所・中小病院で、電子カルテに移行したい | **認証されたクラウドネイティブ型電子カルテ** |
| オンプレ型を使っていて、機器更改が近い中小病院・診療所 | 認証されたクラウドネイティブ型電子カルテ |
| 「今のクラウド製品では機能が足りない」 | 「パッケージ版」電子カルテ（オンプレ型・ノンカスタマイズ・国の医療DXサービスに対応・二要素認証等を実装） |
| 更改が当分先のオンプレ型、大病院 | まず電子カルテ情報共有サービス等への接続（個別改修の支援）。大病院向けクラウドネイティブ型製品は国が開発を支援 |

つまり、**クラウドネイティブ型が本線で、パッケージ版と標準型・導入版は「クラウドネイティブ型が普及するまでの経過的な対応」**と位置づけられています（普及計画 32ページ）。

令和9年度の概算要求には、クラウドネイティブ型電子カルテの普及に336億円（認証製品を導入する医療機関への1/2補助、オンプレ型からのデータ移行費用の1/2補助など）、パッケージ版電子カルテの導入支援に121億円、標準型電子カルテ・導入版に93億円、医療機関のサイバーセキュリティ強化に137億円が並んでいます（普及計画 38〜43ページ。いずれも概算要求の段階です）。

## 3. 普及状況: 病院65.6%・診療所55.0%、クラウドネイティブはまだ一部

### 3.1 医療施設調査（3年ごと）

| 調査年 | 一般病院 | 400床以上 | 200〜399床 | 200床未満 | 一般診療所 |
|---|---|---|---|---|---|
| 平成20年（2008） | 14.2% | 38.8% | 22.7% | 8.9% | 14.7% |
| 平成23年（2011） | 21.9% | 57.3% | 33.4% | 14.4% | 21.2% |
| 平成26年（2014） | 34.2% | 77.5% | 50.9% | 24.4% | 35.0% |
| 平成29年（2017） | 46.7% | 85.4% | 64.9% | 37.0% | 41.6% |
| 令和2年（2020） | 57.2% | 91.2% | 74.8% | 48.8% | 49.9% |
| **令和5年（2023）** | **65.6%** | **93.7%** | **79.2%** | **59.0%** | **55.0%** |

（出所: 厚生労働省「医療施設調査」。電子カルテ普及計画 12ページの表から転記。一般病院は精神科病床のみ・結核病床のみの病院を除く。一般診療所は歯科診療所を除く。平成23年は宮城県の一部と福島県を除く）

令和5年の実数は、一般病院7,065施設のうち4,638施設、一般診療所104,894施設のうち57,662施設です。**3年間の伸びは病院8.4ポイント、診療所5.1ポイント**で、このペースのままでは2030年に約100%には届きません。

### 3.2 直近の数字（2026年6月のアンケート）

社会保険診療報酬支払基金が2026年6月5日〜10日に行ったアンケートを、厚生労働省が集計した結果も普及計画に載っています（13ページ）。対象は医療施設調査と異なり、回答した医療機関が母数です。

| 区分 | 導入済み（回答施設に対する割合） | 未回答を未導入に含めた割合 | 未導入のうち「導入予定なし」 |
|---|---|---|---|
| 医科診療所 | 72.6% | 68.8% | 13,844施設（回答の19.3%） |
| 病院（20〜199床） | 73.5% | 69.8% | 465施設（10.2%） |
| 病院（200〜399床） | 86.0% | 82.8% | 69施設（5.3%） |
| 病院（400床以上） | 94.4% | 92.6% | 5施設（0.9%） |
| 歯科診療所 | 41.5% | 36.8% | 17,384施設（39.0%） |

医療施設調査とは母数が違うので、二つの数字を並べて「3年で何ポイント伸びた」とは言えません。それでも、**医科診療所の約2割が「導入予定なし」と答えている**ことは、2030年目標の難しさを示しています。

### 3.3 クラウドネイティブ型はどのくらいか

医療施設調査には、クラウド型かオンプレミス型かの区分がありません。厚生労働省は2026年3月の資料で、おおまかな内訳を次のように示しています（「電子カルテの普及について」7ページ）。

- **診療所（約10.5万施設）**: オンプレ型の電子カルテ 約4.7万、クラウドネイティブ型 約1万、未導入 約4.7万。「ここ数年で、クラウドネイティブの電子カルテベンダーのシェアが拡大している」
- **病院（約8千施設）**: 200床未満の中小病院でオンプレ型 約3千・未導入 約2千。「小規模病院を中心に、クラウドネイティブの電子カルテが普及し始めている」一方、「現状、病院向けにクラウド型電子カルテを提供しているベンダーが限られている」

電子カルテを使っている診療所のうち、クラウドネイティブ型はおよそ6分の1という計算になります。**病院では、まだ「始まったばかり」**です。

### 3.4 楽観しないための数字

- **日本医師会の調査（2025年8月公表）**: 紙カルテを使っている診療所5,466件の回答のうち、**54.2%が電子カルテの「導入不可能」**と回答。理由は「ITに不慣れ」「導入費用が高額」「導入しても数年しか使用する見込みがない」が多く、高齢の医師ほど「導入不可能」の割合が高い（「電子カルテの普及について」4ページで厚生労働省が紹介）。
- **歯科**: 電子カルテを使う歯科診療所は12%で、カルテ作成支援機能つきのレセコンが79%（厚生労働省の委託調査。普及計画で紹介）。
- **国の推計の前提**: 普及計画の普及推移は「一定の粗い仮定」を置いた推計で、2030年度以降に更改を迎えるオンプレ型は、一定の大規模病院を除いて**すべてクラウドネイティブ型に移行すると仮定**しています（普及計画 26ページ）。この仮定どおりに進むかは、製品の供給とベンダーの体制次第です。

## 4. 標準仕様と認証制度: 「クラウドネイティブ」の要件

### 4.1 標準仕様が求めること（医科診療所・中小病院向け）

普及計画と認証制度要綱が示す、主な「遵守項目」は次のとおりです（普及計画 44ページ、認証制度要綱 別表1）。

| 区分 | 主な要件 |
|---|---|
| 政府の医療DXサービス | オンライン資格確認等システム、電子処方箋管理サービス、電子カルテ情報共有サービス、クラウド型レセコンとの接続に対応すること（電子処方箋・共有サービスは、クラウド間連携の実現後一定期間内の実装を前提に経過措置あり） |
| 可用性 | 直近の稼働率が99.9%以上であること（初回は直近3か月で読み替え。未満の場合は障害の原因分析と再発防止策を提出） |
| セキュリティ | **ISMAP、またはISMS認証＋ISMSクラウドセキュリティ認証**を取得していること（初回申請は経過措置として必須とせず、**2027年6月30日までに取得**）／第三者機関によるペネトレーションテスト（年1回以上が原則）／主要ソフトウェアの脆弱性診断／定期的なセキュリティパッチの適用 |
| データ保管・バックアップ | データを日本国内で保持すること。物理的かつ論理的に隔離された別のクラウドサーバーまたは外部メディアに、定期的にバックアップすること |
| アーキテクチャ | 主なアプリケーションが**ガバメントクラウド対象のクラウドサービスを使ったパブリッククラウド環境**で稼働すること／医療機関に提供するアプリケーションがすべて**SaaS型**であること／**マルチテナント方式**であること／**個々のカスタマイズに対応しない仕様**であること／デジタル庁 GCASガイド「ガバメントクラウドにおけるモダン化の定義」（APIベース・ステートレス・マネージドサービスの活用・運用のコード化など）に合うこと |
| ガイドライン | 「医療情報システムの安全管理に関するガイドライン」等の関係部分に適合すること |
| 情報公開 | 電子カルテの価格（オプションを含む）を自社サイトで公開していること。中小病院向けは機能一覧も公開。連携先や移行先のベンダーから求められたら、連携に必要な事項を開示すること |

ガバメントクラウド（公共SaaS）を利用している製品は、セキュリティ要件のうち外部認証・ペネトレーションテスト・脆弱性診断と、アーキテクチャ要件に適合しているとみなされます。

### 4.2 認証制度の仕組み

- **対象と単位**: 医科診療所向け・中小病院向けの電子カルテを、**製品ごと**に認証します。認証を受けた製品で要件に関わる変更があれば、改めて認証が必要です。後継製品には効力が及びません。
- **有効期間**: 認証対象年度の末日まで。更新は満了日の80日前までに申請します。標準仕様は年次で改訂される予定です。
- **稼働実績**: 申請日の前日時点で、**医科診療所向けは200施設以上、中小病院向けは30施設以上**で稼働し、その状態が直近1年間続いていること（1.0版の初回審査は直近3か月に読み替え）。ガバメントクラウドで構築した製品は、性能・障害復旧などの検証結果の提出に代えられます。
- **ガバメントクラウドの事前相談**: ガバメントクラウドを使っていない製品は、デジタル庁の事前相談を受け、使わない場合はその理由書と技術的指摘への対応計画を出します。
- **申請**: 2026年11月1日〜2027年10月31日、電子メールで標準仕様運営窓口へ。

## 5. 医療機関にシステムを提供する事業者が押さえる論点

### 5.1 電子カルテベンダー: 「認証を取れる構造か」が問われる

認証製品を導入する医療機関には補助を出し、オンプレ型からのデータ移行にも補助を出す——というのが概算要求の設計です。**補助の対象に入れるかどうかが、価格競争力を大きく左右します。** そのためには、パブリッククラウド・SaaS・マルチテナント・カスタマイズ不可というアーキテクチャと、ISMAPまたはISMSクラウドセキュリティ認証、年1回以上のペネトレーションテスト、価格の公開が必要です。医療機関ごとの個別カスタマイズで売上を立てているモデルは、要件と正面から衝突します。

### 5.2 部門システム・周辺SaaS: 「つながる側」の仕様が固まりつつある

標準仕様のシステム連携・データ移行は「次版以降において設定予定」とされ、1.0版では連携共通仕様のイメージ、電子カルテと部門システム間のAPI個別仕様例、業務効率化サービスAPIの実装ガイド（令和8年暫定版）などが示されています。普及計画も、電子カルテ・部門システムの**標準インターフェイス（コード・マスタ等）**を策定する工程を置いています。電子カルテ本体を作らない事業者にとっても、**どのAPIでつながるかは、今後の製品計画の前提**になります。

### 5.3 閉域・オンプレミス前提の製品は、支援策の中心から外れる

パッケージ版（オンプレ型）は残りますが、「クラウドネイティブ型が普及するまでの経過的な対応」です。2030年度以降に更改を迎えるオンプレ型は、大規模病院を除いてクラウドネイティブ型に移る、というのが国の推計の前提でした。**「病院は閉域しか認めないから、オンプレで作る」という判断は、数年先の市場で不利になる可能性があります。** 病院側の「クラウドは怖い」という前提をどう崩すかは、[医療機関サイバーインシデント年表](/articles/hospital-cyber-incident-timeline/)で整理したとおり、侵入の多くが閉域網の外部接続（保守用VPN等）から起きていることが一つの材料になります。

### 5.4 クラウドにすれば終わりではない

標準仕様は、クラウド型であることに加えて、パッチの定期適用、隔離されたバックアップ、第三者の診断を求めています。普及計画も、サイバーセキュリティ対策の強化を電子カルテ普及の前提に置き、2026年6月の経済安全保障推進法の改正で医療分野が基幹インフラに指定されたこと、2025年末ごろから高性能AIによるサイバー攻撃のリスクが高まっていることを挙げています（普及計画 22ページ）。**クラウドは「常に最新に保てる構造」を作りやすいだけで、安全にするのは設計と運用です。** 医療機関からは、厚生労働省ガイドライン第7.0版の要求事項や、サービス仕様適合開示書（SDS）の設問で、その中身を問われます（[ガイドライン第7.0版の改訂まとめ](/articles/guideline-7-0-summary/)）。

### 5.5 新規事業・大学発スタートアップ: ピッチの「市場」の1枚に

医療機関向けのSaaSを構想している事業者にとって、「国がクラウドへ誘導している」ことは市場の説明に使えます。その際は、この記事の出所（医療施設調査の普及率、地域医療介護総合確保法の2030年目標、電子カルテ普及計画、標準仕様の要件）をそのまま示すのが確実です。あわせて、3.4節の「楽観しないための数字」も載せておくと、投資家や審査員からの突っ込みに耐えられます。規制の全体像は「[医療ヘルスケアの新規事業に関わる規制の全体像](/articles/regulatory-map-for-new-business/)」で整理しています。
